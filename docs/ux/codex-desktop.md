# Codex desktop UX 仕様（Android クライアント向け翻訳付き）

## 0. この文書について

- **対象**：Codex desktop アプリ（Windows ストア版 `OpenAI.Codex 26.917.9434.0`。バンドル内部のバージョンは `26.917.71314`）。2026-07 から ChatGPT デスクトップアプリに統合されているので、UI 文言は「Codex」ではなく「ChatGPT」になっている箇所が多い。
- **情報源**：
  1. `app.asar` を展開して得た renderer のロケールファイル（`webview/assets/ja-JP-*.js`、17,071 文字列、305 名前空間）。
  2. 同じ renderer のコマンドレジストリ（`{id:…,title:…}` 形式のスラッシュコマンド定義）と、既定のキーバインド定義。
  3. 公開ドキュメント（learn.chatgpt.com の slash-commands / projects / code-review / remote-connections）。
  4. Codex app-server v2 の JSON Schema（`codex app-server generate-json-schema` で生成）。item の型名と承認の選択肢はここから取った。
- **使い方**：UX 挙動の参考資料としてだけ使う。コードは一切持ち込まない。文言は、挙動を特定するためのラベルとして引用しているだけ。
- **記法**：観察できず推論したものには **(推定)** を付けた。`ns.key` は元のロケールキーで、裏付けを示す。
- Codex desktop にはあっても我々の用途（ローカルの coding agent をスマホから遠隔操作）に無関係な機能は、§8 でまとめて「落とす」と判断している。ChatGPT Work、画像生成、ブラウザ、ペット、音声、Computer Use、Figma などのコネクタがこれにあたる。

## 1. 画面構成と情報設計

### 1.1 ウィンドウの骨格（desktop）

```
┌ rail ┬──────── sidebar ────────┬──────────── thread workspace ─────────────┬─ side panel ─┐
│ Chat │ [モード切替 Codex/Work]  │ threadHeader: タイトル / ⋯ / 分岐 / 別の場所│ Review       │
│ 設定 │ 検索 (Ctrl+K)            │ ─────────────────────────────────────────── │ （差分）     │
│      │ 新しいチャット           │  turn 1: user msg / activity / answer       │ Plan         │
│      │ ── アクティビティ(優先)   │  turn 2: …                                  │ Sources      │
│      │ ── ピン留め              │                                             │ Browser …    │
│      │ ── プロジェクト          │ ─────────────────────────────────────────── │              │
│      │    ▸ projA (chats…)     │ [queued msgs][request-input panel]          │              │
│      │    ▸ projB              │ composer + footer (project/where/branch/     │              │
│      │ ── チャット(プロジェクト外)│   model/permissions/context%)               │              │
│      │ アーカイブ / 接続 / 予定  │ bottom panel: ターミナル / バックグラウンド   │              │
└──────┴──────────────────────────┴─────────────────────────────────────────────┴──────────────┘
```

- **rail**：`sidebarElectron.rail.home` と `rail.settings`、それとモード切替（`productMode.codex` / `work`）。
- **sidebar**：以下の区画で構成される。
  - 新しいチャット
  - 検索（`sidebarElectron.search`）
  - **アクティビティ**（優先ビュー）：`priorityThreads.coachmark.description` のとおり「未読、進行中、要返信のチャットを表示」する。空のときは「対応が必要なものはありません」と出る。
  - ピン留め
  - プロジェクト：プロジェクトごとに折りたためるグループ
  - プロジェクト外のチャット
  - 最下部にアーカイブ・接続・スケジュール（予定済みタスク）へのナビゲーション
- **thread workspace**：タブ化された作業領域。
  - 中央にチャットがあり、右か下のペインに Review・Terminal・Browser・Plan・ファイルを並べる（`threadWorkspace.*`、`thread.bottomPanel.*`）。
  - 全体表示の切り替え（`layout.enterFullView`）とタブの移動（`contextMenu.moveToLeftPane`）がある。
- **アプリ全体のコマンドパレット**：`codex.commandMenu.unifiedSearchPlaceholder`「チャットを検索、またはコマンドを実行」。

### 1.2 主な画面・ダイアログ

| 画面 | 内容 | 根拠キー |
|---|---|---|
| Home（新規チャット） | ヒーロー文と Composer。ヒーロー文は「`<project>` で何を作りますか？」で、プロジェクト名がそのままプロジェクト選択のドロップダウンになる。下に提案カード | `home.hero.whatShouldWeBuildInSelectedProject`, `home.newChatPageSuggestions.*` |
| Projects 一覧 | 名前と更新日の列、検索、ピン留め、編集・削除、プロジェクト内の最近のチャット | `projectsIndex.*` |
| Thread | ヘッダ、ターン列、Composer、下部パネル、サイドパネル | `threadHeader.*`, `localConversation.*` |
| Review パネル | git の差分を scope 別に表示し、stage・revert・commit・PR まで行う | `codex.review.*`, `review.*`, `diff.*` |
| アーカイブ | 種類（ローカル / クラウド / ChatGPT）とプロジェクトで絞り込み、検索、アーカイブ解除 | `sidebarElectron.archivedTasks.*` |
| 設定 | 一般（送信ショートカット、フォローアップの動作、実行中はスリープしない、通知）、エージェント（権限）、Git、Worktree、接続、MCP、フック、使用状況 など | `settings.*`（上位 60 区分） |
| 接続（リモート） | QR / PIN によるペアリング、デバイス一覧（最終接続日・取り消し）、オンライン / オフライン | `codexMobile.*`, `settings.remoteConnections.*` |
| 予定済みタスク | 繰り返しの設定、実行先、今すぐ実行 | `inbox.automations.*` |

### 1.3 情報設計の要点

- 階層は **プロジェクト → チャット（thread）→ ターン → item**。プロジェクトに属さない「スタンドアロンチャット」もある（`codex.command.newProjectlessTask`）。
- 状態は 5 値で表される（`floatingComposer.chatStatus*`）。sidebar の行・プロジェクトのホバーカード・スレッドピッカーで同じ語彙が使われる。
  - `実行中`
  - `承認が必要`
  - `入力が必要`
  - `エラー`
  - `待機中`（idle）
- 状態とは別に「未読の返信」がある。
- プロジェクトのホバーカードには集計が出る：`{n}件が有効`、`{n}件が待機中`、`未読タスク{n}件`。
- 「対応が必要な次のチャット」へ飛ぶコマンドがある（`codex.command.nextThreadNeedingAttention`）。要対応を先頭に集める設計が一貫している。

## 2. Composer の仕様

### 2.1 構成

```
[queued messages…]              ← 実行中に送った送信待ちメッセージ（編集 / 削除 / 今すぐ反映）
[request-input panel]           ← エージェントからの質問（§4.4）
┌─────────────────────────────────────────────┐
│ プレースホルダ / テキスト（@ / $ / の補完）     │
│ 添付サムネイル（画像・ファイル・貼り付けテキスト）│
└─────────────────────────────────────────────┘
footer: [プロジェクト▾][ローカル▾ / 新しい Worktree / クラウド][branch▾ 未コミット:n]
        [モデル·推論▾][権限▾][context 42%]             [送信/停止/キュー/今すぐ反映]
```

- **プレースホルダは状況で変わる**：
  - 新規：`newTask.locally.v2`「Codex に何でも質問。@ でプラグインを使用、またはファイルをメンション」
  - 続き：`localFollowUp.locally`「フォローアップの変更を求める」
  - プラン：`placeholder.plan`「タスクを説明してプランを生成...」
  - ゴール：`placeholder.goal`
  - 実行中：`placeholder.working`「処理中…」
- **Enter の挙動は設定で選ぶ**（`settings.general.enterBehavior`「Enterキーでプロンプトを送信するか改行するか」）。
- **長い貼り付けは自動で添付に変わる**：`fileAttachment.pastedTextLabel`「貼り付けたテキスト.txt」。
- **添付**：写真（`addPhotos`）、ファイルとフォルダ（`addFiles`）、ドラッグ＆ドロップ（`dropOverlay.dropToAttach`）。
  - サイズ上限を超えると `uploadError.fileTooLarge` を出す。
  - 画像に対応しないモデルでは送信をブロックする（`composer.submit.imageInputsUnsupported`）。
- **コンテキスト使用率を表示する**（`contextUsageIndicator`「コンテキスト使用状況: {percent}%」）。設定で非表示にもできる。

### 2.2 スラッシュコマンド（組み込み）

- **開き方**：`/` を入力するとメニューが開き、続けて打つと絞り込まれる。
  - メニュー名は `slashCommands.dialogTitle`「スラッシュコマンド」、説明は「スラッシュコマンドを検索して実行します」、空のときは「コマンドがありません」。
  - スキルは「スキル」グループとして同じメニューに混ざる（`slashCommands.skillsGroup`）。
- **定義の属性**（renderer の登録から）：
  - `requiresEmptyComposer`：たとえば `review-mode` は、入力欄が空のときだけ出る。
  - `enabled`：実行中は無効になる。例は `compact` の「チャットの進行中は Compact を使用できません」。
  - `submenu`：review、fork、model などが持つ。

| コマンド | 意味 | 備考 |
|---|---|---|
| `/new` | 同じワークスペースで空のチャットを開始 | |
| `/fork` | このチャットを分岐（現在のワークスペース / 同じ Worktree / 新しい Worktree） | サブメニューあり |
| `/compact` | コンテキストを圧縮（「(n%使用中)」を表示） | 実行中は不可 |
| `/model` | モデルを選択（「一致するモデル」で絞り込み） | サブメニュー |
| `/reasoning` | 推論レベルを選択 | §2.4 |
| `/plan` | プランモードをオン / オフ | トグル |
| `/goal` | ゴールを設定し、達成まで取り組む | 入力欄が goal モードになる |
| `/review` | コードレビューモード（未コミットの変更 / ベースブランチとの比較 / 特定コミット / カスタム指示） | `requiresEmptyComposer`、サブメニュー |
| `/status` | チャット ID、コンテキスト使用量、レート制限を表示 | |
| `/rename` | チャット名を変更 | |
| `/pin` | サイドバーにピン留め | id は `pin`、ラベルは「チャットをピン留め」 |
| `/archive` | 現在のチャットをアーカイブ | |
| `/init` | AGENTS.md を生成（既にあればスキップ） | |
| `/mcp` | MCP サーバーの状態を表示 | |
| `/side` | 一時的なサイドチャット | 開始前やサイドチャット内では使えない |
| `/local` `/worktree` `/cloud` | 実行場所を切り替え | Worktree には git が必要 |
| `/project` | 新しいチャット用のプロジェクトを選択（「なし」も可） | |
| `/chat` `/task` | プロジェクトなしで開始 | |

| `/fast` | 高速モード（1.5倍速・使用量多め）をトグル | |
| `/personality` | 応答スタイル（フレンドリー / 実用的） | |
| `/memories` `/ide-context` `/share` `/feedback` `/usage` `/pet` `/cloud-environment` | 周辺機能 | 我々は落とす（§8） |
| `/prompts:<name>` | カスタムプロンプト | 公開ドキュメントによる |

### 2.3 メンション・スキル

- **`@`**：ファイル、フォルダ、チャット、エージェント、プラグイン、MCP サーバー、ブラウザタブ、サイトを補完するリスト（`composer.atMentionList.*`）。
  - 空のときは「入力してファイルを検索」、検索中は「ファイルを検索中…」、ヒットなしは「結果がありません」。
  - 結果は「ファイル」「チャット」「スキル」「プラグイン」などのセクションに分かれる。
  - `Tab` で続きを表示する（`pluginMoreShortcut`）。
- **`$`**：スキルやアプリを明示的に呼ぶ（公開ドキュメント「`$` to invoke skills explicitly」、`skillMentionList.*`）。
  - 例：`$skill-creator …`（`home.ambientSuggestions…prompt`）。
- メンションは入力欄の中ではチップ（トークン）として表示される **(推定)**。

### 2.4 ピッカー

- **プロジェクト**（`localCwdDropdown.*`）：
  - 検索できる。
  - 「ローカルプロジェクトを追加」「新しいリモートプロジェクト」「プロジェクトなしで作業」を選べる。
  - スレッド開始後は「このチャットのプロジェクトを変更」として出る。
- **実行場所**（`composer.mode.*`、見出しは「作業場所」）：
  - `ローカルで作業`（現在のブランチで実行、`workLocally.tooltip`「{branchName} で実行」）
  - `新しい Worktree`
  - `既存の Worktree · {name}`
  - `新しいリモートワークツリー`
  - `クラウド`
  - git がなければ「ワークツリーでタスクを実行するには、Git リポジトリを初期化してください」と出る。
- **ブランチ**（`footer.branchSwitch.*`）：
  - 切り替え、作成してチェックアウト、デタッチ HEAD を表示。
  - 未コミットの変更があればダイアログで「コミットしてブランチを切り替える...」へ誘導する。
- **モデルと推論**（`intelligenceDropdown`、ショートカット `Ctrl+Shift+M`）：
  - モデル一覧（カスタムも可）。
  - 推論レベル：`なし / 最小 / 軽 / 中 / 高 / 極高 / 最大 / ウルトラ / パーシステント`。選べる値はモデルによって変わる。
  - 高速モードのトグル。
  - コマンドで推論レベルを上げ下げ・循環できる。
- **権限**（`permissionsDropdown`、タイトルは「Codex アクションの承認方法」）：
  - `承認を依頼`（既定）：外部ファイルの編集やインターネット利用のたびに確認を求める。
  - `代わりに承認`（guardian）：安全でない可能性がある操作だけ確認を求める。
  - `フルアクセス`：確認なしで PC 全体とネットにアクセスする。選ぶと確認ダイアログが出て、影響範囲を「ファイルとフォルダー / ターミナルコマンド / インターネットと連携アプリ」の 3 項目で説明する。
  - `カスタム（config.toml）`
  - 管理対象の設定では無効化される（`disabledByConfig`、`disabledByRequirements`）。
- **レート制限**（`mode.rateLimit.*`）：残り使用量と次のリセット時刻。

### 2.5 実行中に送信したときの挙動（queue と steer）

- **送信ボタンの状態**（`submitButtonTooltip.*`）：
  - `送信`
  - `停止`（実行中で、入力欄が空のとき）
  - `キューに追加`
  - `今すぐ反映`（steer）
  - `再開`
- **既定の挙動は設定で選ぶ**（`settings.general.followUpQueueMode`「フォローアップの動作」）：`キューに追加` か `今すぐ反映`。反対側の挙動は修飾キー付きのショートカットで出せる **(推定：Cmd/Ctrl+Enter)**。
- **キューに入ったメッセージ**は入力欄の上に一覧で出る。各メッセージに次の操作がある。
  - 編集
  - 削除
  - `今すぐ反映`（`sendNowTooltip`「モデルの実行を中断せずに送信」）
  - サイドチャットで開く
- **中断するとキューは一時停止する**（`queuedMessage.interruptedQueue`「中断したため、キューを一時停止しました」）。再開には `再開` を押す。一時停止中に新しく送ろうとすると確認ダイアログが出る（`pausedQueueSubmit`：「キューを消去」か「メッセージを送信」）。
- **送信に失敗したメッセージ**は `pausedTooltip` 付きの状態になり、再試行・編集・削除を選ぶ。
- **送信できないとき**は、理由ごとに具体的なメッセージを出す（`composer.submit.*`）。
  - 作業ディレクトリが消えた
  - Worktree を復元する必要がある
  - リモートが切断されている
  - サンドボックスの設定が必要
  - アップロード中

## 3. スレッド表示

### 3.1 ターンの構造

1. **ユーザーメッセージ**：
   - 右寄せのバブル（**(推定)**）。コピーと編集ができる（`codex.userMessage.editAriaLabel`）。
   - モード表示のバッジが付くことがある：`レビューモード`、`目標として送信`、`PR 修正`、`以前の会話を参照`。
   - フックでブロックされたときは `hookBlocked` と表示する。
2. **作業中の表示**：`作業中`、`{time}作業中`。実行中の行為を 1 行で出す（`agentActivity.*`）。
   - 「{command} を実行中」
   - 「ファイルを編集中」
   - 「{query} をウェブで検索中」
   - 「回答を待っています」
3. **アクティビティのまとまり**：連続したツール呼び出しを 1 ブロックに畳む。
   - 要約は種類ごとに並べる：「コマンドを実行しました」「ファイルを編集しました」「ファイルを読み込みました」「ウェブを検索しました」「ツールを呼び出しました」。
   - 同じツールの繰り返しは「{toolName} · # 回の呼び出し」とまとめる。
4. **最終回答**（agent message）：markdown で全文を表示する。コードブロック、表、mermaid 図、リンクに対応する。
5. **ターン末尾のまとめ**：
   - 変更ファイル数の要約（`unifiedDiff.editedFiles`「# 件のファイルを編集」、`filesChanged`）。
   - `レビュー` ボタンと、`元に戻す` / `再適用` ボタン（このターンの差分を revert / reapply する）。
   - 所要時間（`workedFor`「{time}間作業しました」）。ユーザーが止めた場合は `userStoppedAfter`「{time}後に停止しました」。
   - 評価ボタン（良い回答 / 良くない回答）。

### 3.2 item 型ごとの描画

item 型は Codex の ThreadItem v2 から取った：`userMessage, hookPrompt, agentMessage, plan, reasoning, commandExecution, fileChange, mcpToolCall, dynamicToolCall, collabAgentToolCall, subAgentActivity, webSearch, imageView, sleep, imageGeneration, enteredReviewMode, exitedReviewMode, contextCompaction`。

| item | 描画 | 既定の開閉 |
|---|---|---|
| agentMessage | markdown で全文。ストリーミング中は逐次追記する。読み上げ用に「回答が始まりました / 完了しました」を通知する | 展開 |
| reasoning | 見出し「思考中」→ 完了後は「思考完了」または「思考時間：{elapsed}」。本文は要約 | **折りたたみ** |
| commandExecution | シェル風のブロック：`$ {command}`、cwd ラベル、出力をストリーミング、「出力なし」、コマンドと出力のコピー、展開 / 折りたたみ。状態は「実行中 / 実行済み / 停止済み」 | アクティビティ内では要約 1 行。個別に展開できる |
| fileChange | ファイル単位の行：「作成済み / 編集済み / 削除済み / 移動」と差分のトグル（`patch.change.toggleDiff`）。止められたときは「編集を停止」、却下されたときは「拒否」 | 要約表示。差分は折りたたみ |
| mcpToolCall / dynamicToolCall | 「{connector} の {tool}」＋入力 / 結果（切り詰めて表示）＋パラメータの展開。一部のツールは専用の文言（「チャットを作成中」など） | 折りたたみ |
| webSearch | 「{query} をウェブで検索中」→「ウェブを検索しました」。ソースパネルに件数を出す | 要約 |
| plan（プランモード） | 「プラン」カード（作成中は「プランを作成中」）。サイドパネルで開く、ダウンロード。最後に「このプランを実施しますか？ → はい、このプランを実施します」 | カード展開 |
| todo plan（`turn/plan/updated`） | 入力欄の上に進捗ピル「ステップ {n} / {m}」を出し、展開すると番号付きのステップ一覧 **(推定：ピル位置)** | ピル |
| subAgentActivity / collab | サブエージェントのパネル：モデル · 推論レベル、「# 件作業中 / # 件完了」、すべて停止 | 折りたたみ |
| imageView / imageGeneration | サムネイル（「画像 # 枚を表示済み」） | 表示 |
| contextCompaction | 区切り行：「コンテキストを自動的に圧縮しました / 圧縮中」 | — |
| enteredReviewMode / exitedReviewMode | レビューモードに入った / 出たことを示す区切り | — |
| システム系 | モデル変更（警告付き）、振り分け（reroute）、利用制限、利用制限のリセット、パーソナリティ変更 | 区切り行 |
| エラー | 「このチャット中にエラーが発生しました」「このターンを表示できませんでした」＋再試行 | 表示 |

### 3.3 ストリーミング時の挙動

- 実行中は、最下部にいれば自動で追従する。上へスクロールすると「一番下までスクロール」ボタンが出る（`scrollToBottomButton`）。
- 過去のメッセージは遅延読み込みする（「# 件の過去のメッセージ」）。失敗したら「以前のメッセージを読み込めませんでした」＋再試行。
- 差分・プラン・レビューの「最後のターン」は、ファイルの変更を監視して更新する（`codex.review.fileWatchLimited`）。
- チャット内検索がある（`threadFindBar`「チャットを検索…」）。
- 過去のメッセージから分岐できる（`forkFromOlderTurnDialog`「ここからチャットを分岐」）。

## 4. 承認・質問 UI

### 4.1 配置

- **会話の中にカード**として出る（`approvalRequestCard`）。スレッドの状態は `承認が必要` になり、sidebar の行・ホバーカード・フローティング composer・アクティビティビューのすべてに波及する。
- **既定のキーバインド**：`approval.approve` は `Enter`、`approval.decline` は `Escape`。入力欄やメニューにフォーカスがあるときは無効になる。
- **OS 通知**：
  - 見出しは `codex.notifications.permissionApproval.title`「権限の承認」。
  - 質問の場合は「Codex から質問があります」「続行するには質問に回答してください。」
  - 通知の種類ごとに設定でオン / オフできる（`notifications.permissions`、`notifications.questions`）。

### 4.2 コマンド実行の承認（exec）

- **見出し**：「ChatGPT にこのコマンドの実行を許可しますか？」。ラベル `ターミナル` の下にコマンドを表示し、`理由` 欄がある。
- **選択肢**：
  - `一度だけ許可`（accept）
  - `この会話を許可`（acceptForSession）：補足として「この会話で {command} で始まるコマンドを許可します」を出す。
  - `類似コマンドを許可`（acceptWithExecpolicyAmendment）
  - `拒否`（decline）
  - 閉じる操作は cancel **(推定)**
- **ネットワーク**：「ChatGPT が{destination}に接続することを許可しますか？」。理由として「{host} は現在のネットワーク許可リストに含まれていません」を出す（applyNetworkPolicyAmendment）。

### 4.3 ファイル変更と権限の承認

- **ファイル編集**：「ChatGPT に次のファイルの編集を許可しますか？」＋ファイル一覧（移動は `{source} → {target}`）。
  - 選択肢は `一度だけ許可` / `すべての編集を許可`（「この会話で、今回および今後のファイル編集を確認なしで許可します」）/ `拒否`。
- **権限リクエスト**（`permissionRequest`）：
  - 対象は「{paths} の内容を表示 / 編集」「インターネットに接続」。
  - 付与した分だけを返す（turn スコープか session スコープ）。
- **MCP ツール**：「{connector} に {tool} ツールの実行を許可しますか？」。高リスクなら `高リスク` バッジ。パラメータは展開して見られる。
- **自動レビュー（guardian）**：
  - 状態表示：`自動レビュー中` → `承認されました` / `拒否されました` / `時間切れ`。
  - 却下された操作は `/approve` で 1 回だけ再試行を許可できる。
  - 手動承認が多いと「承認の確認を減らしますか？」という提案が出る。

### 4.4 質問（request_user_input / elicitation）

- 入力欄の上の**パネル**に出る（`requestInputPanel`）。
  - 複数の質問をページ送りする（`前の質問 / 次の質問`）。
  - 選択肢には `label` と `description` があり、`おすすめ` バッジが付くことがある。
  - `isOther` なら自由記述欄（「ここに入力してください」）が出る。
  - `isSecret` なら入力を隠す **(推定：マスク表示)**。
  - 操作は `スキップする` / `送信する` / `続行`。
  - ブロックしない質問は「閉じる、残り # 秒」とカウントダウンして自動で閉じる。
- **回答後**は会話に「質問済み · #件の質問」と残る。回答しなかった場合は「回答が提供されていません」。
- **MCP の elicitation**は `承諾済み / 拒否済み / キャンセル済み` を記録として残す。
- **プラン実施の確認**（implementPlanRequest）も同じ種類の質問 UI で出る。

## 5. プロジェクト/スレッド管理

### 5.1 新しいプロジェクト

- **入口**（`projectSetup.addProjectMenu`）は 2 つ：`最初から始める` と `既存のフォルダーを使用`。
- **作成ダイアログ**（`projectSetup.createProject`）：
  - 種類を選ぶ：`ローカル`（パソコン上のファイルを編集・実行・テスト）/ `リモート`（接続したマシン上のフォルダを選ぶ）/ `クラウド`。
  - 名前を付ける。
  - `ソースフォルダー` を複数追加でき、うち 1 つを `プライマリ` にする。プライマリは AGENTS.md・config.toml・スキルを探す場所になる。
  - デバイスを選ぶ（`このコンピューター` / リモートデバイス）。
- **リモートのフォルダ選択**（`remoteCwdPicker`）：
  - パスの直接入力、フォルダ一覧、親へ移動、「現在のフォルダーを選択」。
  - フォルダがなければ「見つからないフォルダーを作成しますか？」と聞く。
- **編集と削除**：
  - 削除はアプリから外すだけで、ファイルは残る（`removeProject.dialog.description.local`）。
  - フォルダが消えた場合は「このプロジェクトフォルダーは、削除されたか移動されています」と出る。
- **Worktree をプロジェクトとして保存**できる（`createStableWorktree`「HEAD から新しい Git worktree を作成し、プロジェクトとして追加」）。

### 5.2 スレッド一覧の機能

- **並べ替え**：作成日 / 最終更新日時 / 優先度順（要入力・未読を先頭）/ 手動順。
- **グループ化**：プロジェクト別 / 時系列 / 接続先ごと。セクションの並べ替えや、カスタムセクションの作成もできる。
- **行ごとの操作**：
  - ピン留め
  - 名前変更（絵文字も付けられる。「短く、わかりやすく」）
  - 既読 / 未読
  - アーカイブ（実行中なら「停止してアーカイブ」、予定済みタスクがあれば「アーカイブして削除」）
  - 完全に削除（サブエージェントのタスクも含めて消える）
  - エクスプローラーで開く
- **一括操作**：プロジェクト内をすべてアーカイブ、すべて既読。
- **スレッドのヘッダ**（`threadHeader`）：
  - 分岐（同じ Worktree / 新しい Worktree）
  - 別の場所で続ける（新しいチャット / 同じ Worktree / 新しい Worktree）
  - コピー（マークダウン / ディープリンク / セッション ID / 作業ディレクトリ）
  - 新しいウィンドウで開く
  - サイドチャット
- **状態の表示**：スピナー（実行中）、`承認が必要`、`要入力`、未読ドット（`codex.taskRow.unreadDescription`「未読あり」）、エラー **(推定：アイコンの形状)**。

### 5.3 Local / Worktree / Cloud と引き継ぎ

- **Worktree の作成**は進捗を段階表示する：ワークスペース準備 → 最新の変更を取得 → チェックアウト(%) → 環境セットアップ。
  - `更新をスキップ` と `ローカルで作業` にいつでも逃げられる。
  - 失敗時は「Worktree のセットアップに失敗しました」＋`自動修復`。
- **Worktree の自動削除**（ディスク節約）：対象になったチャットには「Worktree がクリーンアップされました → Worktree を復元する」バナーが出る。
- **引き継ぎ**（hand-off）：ローカル ⇄ Worktree ⇄ リモートホストの Worktree へスレッドとコードを移す（`localConversation.moveToLocal/moveToWorktree/threadHandoff`）。引き継ぎ中は送信できない。
- **同時編集の防止**：同じタスクが別の場所で開いていると再開を拒否する（`localTaskRow.resumeLiveWriterError`「このタスクは別の場所で開いています」）。

## 6. 差分レビュー

- **レビューパネルの scope**（`codex.review.source.*` / `stageFilter.*`）：
  - `未コミット`、`ステージ済み`、`未ステージ`
  - `コミット済み`（コミットを選ぶ）
  - `ブランチ`（ベースブランチを選んで比較。表示は `{head} → {base}`）
  - `直近の変更`（旧称は最後のターン）
  - 複数リポジトリのときは repo を選べ、`すべてのリポジトリ` もある。
  - 設定「Git ベースのレビューを無効にする」を選ぶと「最後のターン」だけになる。
- **ファイルツリー**：
  - 変更ファイルの絞り込み（生成ファイルを除外）、ファイルへ移動、確認済み / 未確認のマーク。
  - パスのコピー、エディタで開く。
- **ハンクとファイル単位の操作**（`diff.actionButton.*`）：
  - ステージ / ステージング解除 / 戻す を、ハンク・ファイル・「すべて」の 3 段階で行える。
  - 戻すときは確認ダイアログを出し、「今後は尋ねない」を選べる。部分的に成功した場合も報告する。
- **表示の切り替え**：分割 / 統合、空白の表示、単語単位の差分、折り返し、ファイル全体の読み込み、リッチプレビュー（画像・PDF）。
- **大きな差分**：
  - 「差分が大きいため、ファイルを1件ずつ表示します」（前へ / 次へ）。
  - 大きすぎる場合は「差分が大きすぎて表示できません」。
  - 未追跡ファイルが多すぎる場合は省略し、そのことをバナーで知らせる。
- **インラインコメント**：行に `+` を出してコメントを付け、次のメッセージに添付する（公開ドキュメント、`diffCommentLeftSide/RightSide`）。
- **Git の操作**：
  - コミット：メッセージが空欄なら自動生成する。「ステージされていない変更を含める」オプション、コミット先に新しいブランチを選べる。
  - コミットとプッシュ
  - PR の作成 / 下書き PR の作成 / PR の表示 / PR のマージ
  - `/review` は `レビューモード` の user message を立ち上げる。
- **空の状態**：
  - 「まだファイルの変更はありません」。
  - git がなければ「Git リポジトリを作成する」（その場で git init できる）。
  - 最後の差分がもうなければ「最後のやり取りはコミットされたか、取り消されました」。

## 7. 接続・エラー・空状態

### 7.1 接続まわり

- **スレッド内**：
  - `ChatGPT に再接続中…`
  - ストリームエラーは「再接続中 {n}/{max}」
  - 混雑時は「サーバーが混雑しているため、再接続中」→「{seconds}秒後に再試行」
- **リモートホストのバッジ**（`threadPage.remoteConnectionStatusBadge`）：
  - `接続済み / 接続しています / 切断されました / エラー`
  - 操作として `再接続`、`ログインが必要`、`Codex CLI をインストール / 更新`、`再起動が必要 / 今すぐ再起動`
  - 再起動すると実行中のタスクが止まる旨を tooltip で警告する。
- **sidebar のグループ**：`再接続中…`、`接続に失敗しました`、「タスクを開始するには、この接続を再接続してください」。
- **デバイス接続の状態の語彙**（`settings.remoteConnections.deviceConnections.*`）：
  - 安全な接続を初期化しています / 接続中 / 接続を確認中 / 接続済み
  - デバイスの応答を待っています / 承認が必要
  - オフライン / 切断 / 接続に失敗しました
  - 最終接続日、アクセスを取り消す
- **ペアリング**（`codexMobile.*`）：
  - PC 側が QR コードを表示し、全画面表示や更新ができる。8 桁の PIN による手動ペアリングもある。
  - 接続後に `この PC をスリープ状態にしない`（電源接続時、かつリモート有効時）を案内する。
  - 設定には `実行中はスリープしない` もある。
  - モバイルでできることとして「中断したところから再開」「新しいことを始める」「最新情報をチェック（完了時・対応が必要なときに通知）」の 3 つを挙げている。
- **ホストが寝ている / オフラインのとき**：「コンピューターが利用可能になるまでリモートアクセスは止まる」（公開ドキュメント）。常時起動の PC を推奨している。

### 7.2 エラー

- **CLI 接続**（`appServer.error.*`）：
  - 問題発生時は「再起動してみてください」
  - ログアウト中
  - リモートに CLI がない
  - バージョンが古い（min と current を表示）
  - 更新後の再起動待ち
- **クラッシュ**（`appServerCrash`）：「問題が発生しました」→ 再起動 / 設定を確認 / フィードバック。
- **その他**：
  - 利用制限：リセット日時、アップグレード、クレジット購入。
  - ターンの描画に失敗：再試行。
  - 作業ディレクトリが消えた：Worktree を復元。

### 7.3 空状態

| 場所 | 表示 |
|---|---|
| Home | 「何を作成しましょうか？」または「`<project>` で何を作りますか？」＋提案 |
| プロジェクト | 「プロジェクトはありません → 新規プロジェクト」 |
| チャット | 「チャットはありません」 |
| アクティビティ | 「対応が必要なものはありません」 |
| アーカイブ | 「アーカイブ済みのタスクはありません」 |
| レビュー | 「まだファイルの変更はありません」 |
| ターミナル | 「まだ出力がありません」 |
| デバイス | 「まだデバイスは追加されていません」 |

## 8. Android への翻訳

前提：我々のアプリは Kotlin + Jetpack Compose のスマホ単一カラムで、agent-app-server daemon（自宅の Windows PC）に foreground service 経由で常時接続する。

- この章の API 名は `docs/protocol.md` と `crates/aas-protocol` に合わせてある（2026-09 に照合）。食い違いに気づいたら、型が正しいのでこの章を直す。
- この章はアプリ（`android/app`）の実装と一致させてある（2026-09 に照合）。画面ごとの詳しい対応は `docs/android.md` の 24〜27章、desktop の挙動から変えた点とその理由は同 28章。
- 「アプリ側」と書いたものは daemon の API を使わず、アプリだけで処理する。
- desktop にあっても設計の範囲外（`docs/design.md` 1章「範囲外」）のものは §8.4 に理由付きでまとめ、ほかの節には書かない。

### 8.1 そのまま移植する（1:1）

| Codex desktop | Android での実装 |
|---|---|
| プロジェクト → チャット → ターン → item の階層 | 画面遷移で表す：`Projects`（`project/list`）→ `Threads(project)`（`thread/list`）→ `Thread`（`thread/read` のあと `subscribe`） |
| 5 状態＋未読の語彙（実行中 / 承認が必要 / 入力が必要 / エラー / 待機中 / 未読） | 同じ語彙のチップや色ドットで、全リストと通知に統一して使う。<br>実行中は `Thread.status`（`running` など）。承認が必要 / 入力が必要は保留中の Interaction の `request.kind`（`approval` / `question`。`workspace/snapshot` の `pendingInteractions` と `interaction/pending` / `interaction/closed`）。エラーは `Thread.lastError` と `lastTurn.status: failed`。<br>未読はアプリ側（端末ごと。`Thread.head` と端末に保存した読んだ位置を比べる） |
| アクティビティ（優先）ビュー | 下部ナビの独立タブ **「要対応」**。保留中の承認・質問（workspace ストリーム）、エラー、未読を横断して並べる。バッジは件数 |
| item の描画ルール（reasoning は畳む、コマンドはシェル風ブロック、アクティビティはまとめて要約、回答は markdown で全文） | そのまま使う（Item の `kind` ごと）。連続する思考・コマンド・ファイル変更・ツール（2件以上）は1つのまとまりに畳み、種類ごとの件数で要約する。実行中のターンの最後のまとまりは開いておく |
| 送信ボタンの状態（送信 / 停止 / キュー / 今すぐ反映）、送信待ちメッセージの編集・削除・今すぐ反映、中断時のキュー一時停止 | そのまま使う。実行中の送信の既定（キューに追加 / 今すぐ反映）は設定で選び、**長押しで反対側の挙動**。<br>送信は `turn/start`（実行中でなければ `delivery: auto`、実行中は `queue` / `steer`。能力 `steer`（`capabilities.steer`）がなければキューだけ）、停止は `turn/interrupt`。送信待ちの一覧は `thread/read` の `queued` と `queue/updated`。編集は `queue/update`、削除は `queue/remove`、今すぐ反映は `queue/steer`（実行中なら steer、実行中でなければ新しいターン）。「今すぐ反映」は、実行中のときだけ能力 `steer` を条件にし、実行中でなければどのハーネスでも出す（新しいターンを始めるだけなので能力は要らない）。一時停止は `Thread.queuePaused` で、再開は `queue/resume`。一時停止中に送信すると「送信する（キューも再開）/ キューを消去して送信 / キャンセル」を確認する |
| 承認の選択肢（一度だけ / この会話で / 類似コマンド / すべての編集 / 拒否）と説明文 | そのまま使う。選択肢は daemon が harness 固有のものを正規化して渡すので（`ApprovalOption.kind`）、UI は受け取った選択肢を描画して `interaction/respond` で答えるだけ |
| 質問パネル（複数の質問、おすすめ、その他の自由記述、スキップ） | ボトムシートで1問ずつページ送りする（単一・複数選択、自由記述）。スキップは `interaction/respond` の `dismissed` |
| 権限ピッカー（承認を依頼 / 代わりに承認 / フルアクセス＋3 項目の警告ダイアログ） | ボトムシート。選択肢はハーネスの `permissionModes`（空なら出さない）で、変更は `thread/update` の `settings.permissionMode`。`PermissionMode` には危険度がない（id・名前・説明・既定かどうかだけ）ので、「フルアクセス＋3 項目の警告」の代わりに、既定以外のモードを選ぶときはそのモードの説明を出して確認する（id から危険度を推測しない） |
| モデルと推論のピッカー | ボトムシート。モデルはハーネスの `models`、推論レベルは `effortLevels`（モデルに `effortLevels` があればそれに絞る）。変更は `thread/update` の `settings`（応答の `settingsOutcome` で即時反映か次のターンからかを表示する） |
| `/` メニュー（アプリ側のコマンドと harness 固有のコマンドを統合）、`@` ファイル、`$` スキル | 入力欄の直上に一覧を出す（composer の一部なので IME の上に残る）。`/` は本文の先頭の単語にカーソルがある間、`@` は単語の先頭の `@` にカーソルがある間に開く。`/` の一覧は `command/list`（daemon のアプリ用コマンドとハーネスのコマンド）とアプリ側のコマンド（§8.5）で、前方一致、部分一致の順に絞り込む。Codex のスキルは `$名前` を挿入するハーネスのコマンドとして `/` の一覧に入る（`$` で開く一覧は持たない）。`@` は `fs/search`（打鍵が止まってから問い合わせる）。`commands/changed` を受けたら取り直す |
| 接続状態の語彙とバナー（再接続中 n/max、接続済み、切断、ホストがオフライン） | アプリ側。画面上部の接続バー（色のドット、状態、詳細「n 回目の再試行 · 送信待ち n 件 · 最終同期 n 分前」、再試行待ちなら「再接続」。押すと診断画面）と、操作が必要なときの注意のバナー（別の場所で接続中 →「この端末で接続」、失効・トークンの拒否 →「ペアリング」など）。スレッド画面はオフラインのとき、端末に保存した内容を表示していると出す。**スマホ側がオフライン**と**PC 側に届かない**を区別して表示する。再試行は上限なしでバックオフしながら続けるので、回数だけを出す（desktop の n/max の max はない） |
| ペアリング（QR、手動コード）とデバイス管理（最終接続日、取り消し） | カメラで QR を読むか、コードを入力する（`POST /v1/pair`）。デバイスの一覧（最終接続日時、この端末に印）と取り消しは `device/list` / `device/revoke`（daemon の CLI の `devices` / `revoke` でもできる） |
| 「実行中はスリープしない」 | daemon の設定（`policy.prevent_sleep_while_running`）。アプリの設定では `server/status` の `preventSleepWhileRunning` を表示する |
| 通知の種類（承認 / 質問 / ターン完了の「常に / 見ていないときだけ / 通知しない」） | アプリ側。通知チャンネルを種類ごとに分け、承認・質問・エラーのオン・オフとターン完了の「常に / 見ていないときだけ（既定）/ 通知しない」をアプリの設定に置く（§8.3） |

### 8.2 スマホ向けに作り直す

- **ナビゲーション**（アプリ側）：下部ナビに `プロジェクト` / `要対応` / `設定` を置く。スレッド画面は全画面にする。サイドパネルは別画面かボトムシートにする。
  - Review → 「変更」画面（スレッドのメニューとターンの末尾の「差分を見る」から開く）
  - Plan → composer の上のプランのピル（「プラン n / m 完了」と進行中の項目。押すと一覧を開閉する）
  - Sources → 専用のパネルは持たない（§8.4）。検索・取得したものは toolCall（category `search` / `fetch`）の Item として会話に出る
- **スレッドの操作**：sidebar のホバーカードや右クリックメニューは、**長押しメニューとスワイプ**に置き換える。
  - 右スワイプで既読 / 未読（アプリ側。端末ごとの状態）
  - 左スワイプでアーカイブ（`thread/archive`）。スナックバーの「元に戻す」で解除できる。プロセスがあるなら「停止してアーカイブ」を確認する（`thread/archive` はプロセスを止めてから応答する）
  - 長押しメニュー：ピン留め / 外す（`thread/update` の `pinned`。ピン留めしたスレッドは一覧の先頭にまとめる）、名前変更（`thread/update` の `title`）、既読 / 未読、アーカイブ
  - スレッド画面のメニュー：名前を変更、ピン留め、分岐（能力 `fork`）、変更、状態、新しいスレッド、未読にする、プロセスを停止（確認あり）、アーカイブ / 解除
- **Composer の下部**：desktop の footer は横幅が足りない。本文の下にスクロールできるチップ列を置く：`[harness·model·推論] [権限] [ctx 42%]`（ほかに、変更の送信待ちがあればその件数）。実行場所とプロジェクトはスレッド作成時に決めて、以後は表示専用にする。
  - `ctx NN%` は `Usage.context` の `usedTokens / windowTokens`。実行中のターンは `turn/usageUpdated`、それ以外は `Thread.usage.context` を使う。ハーネスが報告しない（`context` がない）場合はチップを出さない（推定しない）。押すと状態のシート（`/status`）を開く。
- **承認**：
  - 会話中のカードに加えて、**入力欄の上に固定バナー**を出す（カードが画面外にあっても見落とさない）。押すとカードへスクロールする（質問は回答シートを開く）。「要対応」タブのカードからもその場で答えられる。
  - ボタンは大きく、`拒否` と `許可`（一度だけの許可。なければ範囲の広い許可）の 2 つを主にし、それ以外（この会話で / 類似 / 常に / 理由付きの拒否）は `⋯` にまとめる。理由付きの拒否はダイアログで理由を書く。
  - 誤タップ対策として、ボタンはカードが出て（または動いて）から 0.5 秒（`AppPolicy.interactionArmDelayMs`）押せない **(desktop にはない配慮)**。
  - 回答が送信待ち（outbox）の間は「回答は送信待ちです」と出し、ボタンを無効にする。
  - **通知のアクション**は `許可（一度だけ）` と `拒否` の 2 つだけにする（その 2 つの選択肢があるときだけ出す）。範囲の広い許可（この会話で / 常に / フルアクセス）と理由付きの拒否は、アプリを開かないと選べないようにする（ロック画面で広い許可を出させない。ボタンはロックの解除を求める）。
- **質問**：通知から開くとボトムシートが直接開く。ハーネスが質問を取り下げたら（`interaction/expired`、`harnessCancelled`）シートを閉じる。アプリ独自のカウントダウンは持たない（§8.4）。
- **差分**：
  - 分割表示はなしで、**統合表示だけ**にする。
  - ファイル一覧（`thread/diff` の `files`）と、ファイルごとの見出し・hunk の見出し・旧と新の行番号付きの差分（横スクロールか折り返しの切り替え）。パッチは `thread/diff` の `patch`、大きければ `patchBlobId`（`GET /v1/blobs/{id}`）で取り、アプリ側でファイルごとに分ける。差分が大きいとき（`AppPolicy.diff.oneFileAtATimeLines` 行を超える）は 1 ファイルずつ（前 / 次）表示する。
  - 表示できないほど大きいファイル・バイナリ・パッチにないファイルは理由を出す（大きすぎるものは「PC で確認」）。パッチ自体が大きすぎればファイルの一覧だけを出す。
  - スコープはターン（`scope: {kind: "turn"}`）とスレッド（`scope: {kind: "thread"}`）。ターンから開いたときはタブで「このターン」と「スレッド全体」を切り替える。ステージ・戻す・コミット・プッシュ・PR は持たない（§8.4）。
- **インラインコメント**（アプリ側）：行を長押しして「この行にコメント」→ スレッドの下書きに「`path:行` と引用 + コメント」を足す（テキストとして次のメッセージで送る）。
- **新規プロジェクト**：
  1. 「既存のフォルダーを使用」を選ぶと、daemon の `fs/roots` と `fs/list`（許可した root 配下だけ。git リポジトリに印）をたどるフォルダピッカーになる。パスの直接入力もできる。どちらも `project/open` で登録する。
  2. 「最初から始める」を選ぶと、始め方（空 / `git init` / `git clone`）と clone の URL とフォルダ名 → 置き場所（`fs/roots` と `fs/list`、必要なら「新しいフォルダー」で `fs/mkdir`）→「ここに作成」の順で進む（`project/create` の `init`）。フォルダ名は、利用者が打つまでは clone の URL の最後の要素に従う（`git clone` と同じ）ので、名前を置き場所より先に聞く。
     - clone は Operation になる。`operation/updated` の `progress`（git の進捗の行をそのまま）を表示し、`取り消す` で `operation/cancel` を呼ぶ。失敗したら `message` を表示する。画面を閉じても clone は続き、プロジェクト一覧に進捗が出る。資格情報が必要なリポジトリは PC 側で入力を待たずに失敗する。
  3. 作成すると最初のスレッドの作成画面へ進む。既存のフォルダを開いた場合は、スレッドのないプロジェクトのときだけ進む（アーカイブから戻ったプロジェクトなど、スレッドがあればスレッド一覧を出す）。
  - ソースフォルダを複数持つ構成は落とす（理由は §8.4）。
- **スレッド作成時の指定**：harness、モデル、推論レベル、権限、実行場所（ローカル / 新しい Worktree。git リポジトリのときだけ）を 1 つの画面で選び、同じ画面で最初のメッセージを書く（`thread/create` の `harnessId` / `settings` / `workspace` / `input`）。既定値はプロジェクトの `defaults` から取り、作成したらアプリが `project/update` で `defaults` を今回の値に更新する（「前回値を引き継ぐ」）。
- **サブエージェントとバックグラウンドのプロセス**：サブエージェントは `toolCall`（category `subagent`）の Item として読み取り専用で表示する。`すべて停止` はスレッドのメニューの「プロセスを停止」（確認あり）と `/stop` で、`thread/stop`（エージェントと、エージェントが起動したプロセスをツリーごと止める。次の入力で再開できる）。個々のプロセスの一覧は持たない（§8.4）。
- **入力**：音声入力は OS の IME のものを使う（独自の音声機能は持たない）。画像はカメラかギャラリーから添付する（1 通に `AppPolicy.maxImagesPerMessage` 枚まで。PNG / WebP / GIF で上限以下ならそのまま、JPEG は向きを反映して位置情報などのメタデータを落として作り直し、それ以外と上限を超えるものは長辺 2048px 以下の JPEG にしてから `POST /v1/blobs` → `InputPart` の `image`）。ハーネスの能力 `images` がなければ添付ボタンを出さず、添付したあとで画像を受け付けないハーネスに切り替えたら、画像を外すまで送信できない。

### 8.3 通知の設計（desktop の設定を翻訳）

通知はすべてアプリ側で出す（FCM は使わない。foreground service の接続で受けたイベントから出す）。

| channel | 重要度 | 内容 | アクション |
|---|---|---|---|
| `approvals` | HIGH（heads-up） | コマンド / ファイル / 権限 / MCP の承認要求（`interaction/pending`）。本文に題名、詳細、対象（コマンド 1 行、ファイル数と名前、ツール名など）。ロック画面には詳細を出さない | 拒否 / 許可（一度だけ）/ 開く（承認カードまでスクロール） |
| `questions` | HIGH | エージェントからの質問 | 開く（シートへ直接） |
| `turns` | DEFAULT | ターンの完了（「{time}間作業しました」。`startedAt` と `completedAt` から）と中断、clone の完了（アプリが背面のとき）。設定は「常に / アプリを見ていないときだけ（既定）/ 通知しない」 | 開く |
| `errors` | DEFAULT | ターンの失敗（エージェントのクラッシュ、再開の失敗など。`Turn.error.kind`、`Thread.lastError`）、clone の失敗、アプリが背面のときにサーバが確定エラーで断った要求、通知のボタンの回答を送信待ちにできなかった場合 | 開く |
| `connection` | LOW（常駐） | foreground service の常駐通知：接続バーと同じ文言（接続済み / 再試行待ちと次の試行までのカウントダウン / 送信待ち n 件（outbox）など） | 今すぐ再接続 |

- ターンの通知はスレッドごとに 1 つで、次のターンの通知で置き換わる。承認・質問は Interaction ごとに 1 つ、断られた要求はスレッドごとに 1 つ（最新の失敗）。本文は BigTextStyle で出す。
- 承認が解決・失効したら、別の端末で解決した場合も含めて、該当する通知を消す（`interaction/closed`）。スレッドを開いた・既読にしたら、そのスレッドのターン・エラー・断られた要求の通知を消す。
- 表示中のスレッドの承認・質問は、音と heads-up なしで出す（画面のカードで見える）。
- Android はパッケージごとに 50 件を超える通知を黙って捨てるので、`AppPolicy.notificationBudget`（40 件）を超えたら古いターン・エラー・clone・断られた要求の通知から消す（承認・質問と常駐通知は消さない）。

### 8.4 落とす（理由付き）

| 機能 | 理由 |
|---|---|
| 統合ターミナル（チャットごとの PTY） | スマホのキーボードでシェル操作するのは苦痛。ANSI 表示のコストも高い。エージェントが実行したコマンドの出力を読むだけで用途は満たせる（design.md の範囲外） |
| git の書き込み操作：ハンク・ファイル単位のステージ / ステージ解除 / 戻す、ターン差分の「元に戻す / 再適用」、コミット、プッシュ、PR の作成・マージ、ブランチの切り替え | design.md 1章の範囲外（git の書き込み操作の UI）。エージェントに頼めば実行でき、スマホでの誤操作は取り返しがつきにくい。差分の閲覧は §8.2 のとおり持つ |
| ブラウザパネル、Computer Use、appshot、ペット、音声チャット、画像プレイグラウンド、Work モード、ChatGPT のチャットやメモリ、プラグインのマーケット | coding agent の遠隔操作という目的の外にある |
| クラウド実行と `/cloud` | 実行するのは自宅 PC の daemon だけ。クラウドは別製品の範囲 |
| 予定済みタスク（automations） | daemon 側にスケジューラが必要で、今回の対象外（design.md の範囲外） |
| 複数ソースフォルダのプロジェクト、リモートホストの選択 | daemon は 1 台の PC だけ。harness の多くは cwd を 1 つしか扱えない（プライマリフォルダ 1 つに相当） |
| `/side`（サイドチャット）、タブ、ペイン、新しいウィンドウで開く | 単一カラムの画面では意味がない。「新しいスレッドで続ける」で代用する |
| 自動レビュー（guardian）と `/approve` | Codex 固有で、harness を問わない形では実現できない。Codex のスレッドでは、権限ピッカーに「代わりに承認」に当たるモードがあれば、それが `permissionModes` に出る |
| `/goal`（ゴール）と `/mcp`（MCP サーバの状態） | ハーネス固有で、ハーネスをまたいで正規化できるシグナルがない（design.md の範囲外）。アダプタがハーネスのコマンドとして公開すれば、`/` メニューに `insertText` のコマンドとして出る |
| ブロックしない質問のカウントダウンと自動クローズ | 締め切りを報告するハーネスがなく、アプリが時間を計ると推測になる（design.md の範囲外）。ハーネスが取り下げたら `interaction/expired` で閉じる |
| バックグラウンドのプロセスの一覧 | Job Object の中のプロセスはハーネスをまたいで意味のある名前を持たない（design.md の範囲外）。実行中の commandExecution / toolCall の Item を表示し、止めるのは `thread/stop` |
| 高速モードと `/fast`、パーソナリティ、`/memories`、`/ide-context`、`/share`、`/feedback`、`/usage`、`/pet` | 特定のサービスに依存するか、desktop 固有 |
| git blame、定義へ移動、リッチプレビュー（PDF など） | スマホでの差分レビューの範囲を超える |
| Sources パネル（参照した情報源の一覧） | プロトコルに情報源を正規化した型がなく、ハーネスをまたいで集められない。Item の本文や URL から拾い集めるのは推測（ヒューリスティック）になる。検索・取得は toolCall（category `search` / `fetch`）の Item として会話に出る |

### 8.5 スラッシュコマンド：我々のアプリでの対応表

`action` の種類（`Command.action`）：`insertText` は composer にテキストを挿入する（送るとハーネスがコマンドとして処理する）、`method` は daemon の API を呼ぶ（`clientRequestId` と `threadId` はアプリが補う）、`picker` は選択 UI を開く。「アプリ側」は `command/list` には入らず、アプリが自分で `/` メニューに足す（同じ名前のコマンドを daemon が返したときは足さない）。`/` メニューの並びは daemon のアプリ用コマンド（`source: "app"`。アプリが日本語の説明を付ける）、アプリ側のコマンド、ハーネスのコマンドの順。新しいスレッドの composer では、アプリ側のコマンドは `/review` と `/init` だけを出す。

| コマンド | 我々での扱い | action |
|---|---|---|
| `/new` | 同じプロジェクト・同じ harness の新しいスレッドの composer を開く。最初の送信で `thread/create`（`input` 付き）を呼ぶ | アプリ側 |
| `/fork` | 分岐する（`command/list` の `fork`。harness の能力 `fork` があるときだけ入っている） | method `thread/fork` |
| `/compact` | ハーネスのコマンド（Codex はアダプタが `thread/compact/start` を呼ぶ、Claude は CLI のスラッシュコマンド。pi は公開していない）。実行中に送ると通常の入力と同じくキューに入る | insertText `/compact` |
| `/model` | モデルのピッカー（`command/list` の `model`。ハーネスにモデルの一覧があるときだけ入っている） | picker `model` |
| `/effort`（desktop の `/reasoning`） | 推論レベルのピッカー（`command/list` の `effort`。ハーネスに推論レベルがあるときだけ入っている） | picker `effort` |
| `/permissions` | 権限モードのピッカー（`command/list` の `permissions`。ハーネスに権限モードがあるときだけ入っている） | picker `permissionMode` |
| `/plan` | `/` メニューには入れない（専用のメソッドはない）。Claude のプランモードは権限モード `plan` なので、`/permissions` で選ぶ（`thread/update` の `settings.permissionMode`） | —（`/permissions` の picker `permissionMode`） |
| `/review` | Codex はハーネスのコマンド `review`（アダプタが `review/start` を呼ぶ）。他の harness ではアプリが定型のレビュー依頼文を composer に挿入する | insertText（Codex）/ アプリ側 |
| `/status` | スレッド ID、harness のネイティブ session ID（`nativeSessionId`）、コンテキスト使用率（`usage.context`）、プロセス状態（`status`。`idle` はプロセスなし）をシートで表示する | アプリ側 |
| `/rename` | 名前変更のダイアログ → `thread/update` の `title` | アプリ側（method `thread/update`） |
| `/pin` | ピン留め / 外す → `thread/update` の `pinned` | アプリ側（method `thread/update`） |
| `/archive` | アーカイブ（`command/list` の `archive`） | method `thread/archive` |
